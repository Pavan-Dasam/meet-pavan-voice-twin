2. Voya Policy Servicing Agent — Single Agentic System
- Single Agentic System — per Voya Financial's requirement
- Context: Beyond claims, Voya's policy servicing team handles endorsements, beneficiary updates, billing inquiries and policy document requests. Rather than a multi-agent pipeline, delivered a single agentic system — one LLM-driven agent equipped with multiple tools — that reasons over each request end-to-end and decides which tool to call, matched to how self-contained this workflow is.
- Single-Agent + Tools Workflow: Incoming Request → Single Agent (reasoning loop) → Tool Calls: Policy Change Tool | Billing Lookup Tool | Document Retrieval Tool | Compliance Check Tool → Response
- Technologies: LangGraph (single-agent loop), MCP, Azure OpenAI, Python, FastAPI, Azure AI Search, PostgreSQL, Docker, AKS
- Technical Details:
  * Designed a single agentic system — one LangGraph agent running a continuous reasoning-and-tool-calling loop, not a multi-agent pipeline — since policy servicing requests are typically self-contained and well-suited to one agent with the right tools.
  * Exposed policy-change, billing-lookup, RAG-based document-retrieval and compliance-check capabilities as MCP tools that the single agent calls directly, keeping one continuous context and one audit trail per request instead of handing off between agents.
  * Implemented persistent agent state so the same agent handles multi-turn requests — e.g., a beneficiary update followed by a compliance re-check — without losing context, with human-in-the-loop approval inside the same loop for changes above a defined risk threshold.
  * Deliberately chose this single-agent, tool-calling design over a multi-agent pipeline for policy servicing, reserving the multi-agent approach for the higher-complexity claims workflow above.
